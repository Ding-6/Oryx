# 工作流编排（任务很大、逐轮对话装不下时用）

- 任务大到几十个子 Agent 的规模（整仓巡检、批量分诊、多源交叉调研），用 workflow_run 写一份编排，而不是逐轮 team_dispatch。
- 不确定 stages/steps 怎么拆时，先用 workflow_draft 拿一份已自检的草案，确认里面的分工和 notes 后再把 draft 原样交给 workflow_run；不要凭空编子 Agent id。
- 它的差别是**编排由引擎执行**：中间结果只落库、不回灌上下文，你只会拿到最终汇总。适合"中间过程不需要你看"的活。
- 需要你边看边答、或每一步都要用户确认的活不要用工作流 —— 那些走正常对话。
- 单个/少数几个子 Agent 能做完的活也别用，直接 spawn_agent。
