# 扩展目录

这里的每个子目录是一个扩展。放进去就能被 Oryx 发现 —— **不用改 Python**。

## 两种扩展

| 类型 | 入口文件 | 放哪 | 能执行代码吗 |
|---|---|---|---|
| 技能 | `SKILL.md` | `skills/` | — |
| 工具 | `oryx.json` + `tools.py` | `extensions/` 或用户目录 | 看信任级别 |

## 信任级别（决定能不能执行代码）

| 目录 | 信任级别 | 工具代码 |
|---|---|---|
| `%APPDATA%/Oryx/extensions`（用户自己的） | `user` | ✅ 可执行 |
| 本仓库的 `extensions/` | `project` | ❌ **只声明元数据，不执行** |

> **为什么仓库自带的不能执行**：`git clone` 一个仓库不该等于授权它的代码
> 在你机器上跑。所以仓库里的扩展只能声明「这个工具叫什么、干什么、
> 参数长什么样、有多危险」，实现不会被执行。

想让仓库里的工具真的跑起来，两个办法：
1. 把扩展目录**复制**到用户目录（`%APPDATA%/Oryx/extensions`）；
2. 或者把它当成**元数据声明**用 —— 工具的名字与描述会进入索引，
   供路由与提示词参考，但不会注册为可调用工具。

## 一个例子

`word-count/` 是一个最小样例：

- `oryx.json` —— **声明层**：工具名、描述、参数 schema、**风险等级**、实现位置
- `tools.py` —— **实现层**：函数实现，约定返回 `{"ok": bool, "content": str, "meta": dict}`

风险等级写在清单里而不是代码里 —— 这样「这个工具会干什么、有多危险」
可以在**不执行任何代码**的情况下审阅。

| 等级 | 含义 | 举例 |
|---|---|---|
| `L0_READ` | 只读 | 读文件、查状态 |
| `L1_WRITE` | 可逆写入 | 写文件、生成文档 |
| `L2_DESTRUCTIVE` | 破坏性 | 删除、覆盖、移动 |
| `L3_FORBIDDEN` | 禁止 | 永远不做 |

**没写风险等级 → 按 `L2` 处理**。宁可严一点：未知工具会被审批流程拦一下。

## 查看加载情况

```bash
# 运行时
curl -H "X-Oryx-Token: $TOKEN" http://127.0.0.1:8765/api/extensions
```

返回里 `tool_report` 会说明：加载了哪些、跳过了哪些、为什么跳过、
执行了哪些代码文件。

## profile

用 `profiles.json` 按组合启用扩展。在配置里选：

```json
{ "extension_profile": "developer" }
```

`developer` 包含 `minimal`（`includes` 嵌套）。**profile 只收窄范围，
不影响安全判定** —— 它不能用来绕过信任检查。
