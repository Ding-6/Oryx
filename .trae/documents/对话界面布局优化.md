# 对话界面布局优化（对标 Marvis）

## Context

上一批改造补齐了思考过程、会话续接、图库过滤、技能广场聚合，功能层面已对齐 Marvis。但**界面布局**仍有明显差距 —— 用户这次明确要求「分析 Marvis 的对话界面布局，优化我的项目」。

我用 reverse-engineer-anything 技能对 Marvis 做了静态分析（主 bundle `treemap-KZPCXAKY-DqrP9bPu.js` 8.26MB + 主 CSS `treemap-KZPCXAKY-DLtJrR72.css` 1.17MB，REA 图谱 1316 文件 / 3004 findings），并把 Oryx 现状逐条对照。

### 逆向提取到的 Marvis 事实

**Marvis 侧栏**：`.semi-ai-chat-dialogue-wrapper`（行容器，padding `8px 16px`，`column-gap:16px`）→ `.semi-ai-chat-dialogue-container`（`column-gap:12px`）→ `.semi-ai-chat-dialogue-inner`（`flex-direction:column`）→ `.semi-ai-chat-dialogue-avatar`（**24×24**）+ `.semi-ai-chat-dialogue-content`（**font-size:16px**）。

**Marvis 气泡**：
- 用户：`.semi-ai-chat-dialogue-content-userBubble` —— `padding:20px`、`border-radius:20px`、`max-width:600px`、`min-width:66px`、`min-height:60px`、底色 `linear-gradient(#7b483514, #fff)`
- 助手：**无气泡背景**，纯文本左对齐（`.semi-ai-chat-dialogue-content-inner` 在右侧容器里 `text-align:right`，但内部 markdown `text-align:left`）

**Marvis 操作栏**：`.semi-ai-chat-dialogue-action` —— `margin-left:54px`（精确对齐头像列：wrapper padding 16 + avatar 24 + gap 12 ≈ 52~54）、`visibility:hidden` → `:hover` 时可见、按钮 24×24（复制 / 重试 / 更多）

**Marvis 思考面板**：`${Ht}-ai-chat-dialogue-reasoning` —— wrapper `border-radius:12px` + `border:1px solid` + `cursor:pointer`；header `padding:16px`、`justify-content:center`、prefix/suffix 图标 20×20、title `font-weight:600`；content `padding:12px 16px` + `border-top:1px solid`。组件实现（bundle `@2005425`）：`status !== "completed"` → `useState(true)` 默认展开，点击 wrapper 切换，Enter/Space 同样切换。

**Marvis 响应式机制**（最关键的一条）：`ResizeObserver` 实时测量容器 → 写 CSS 变量 `--input-box-width` / `--dialog-width`（bundle `@5625506`）。断点常量 `A4=1004, ZS=700, UZ=500, V3=380`（bundle `@5624530`），列宽公式 `min(1004px, calc(100% - 88px))`。容器查询 `@container xiaobao-agent-chat-dialogue-container (max-width: 606px)`。

**Marvis 侧栏**：`._sidebar_nvbqm_28` —— 88px 收窄态，hover/展开 196px，`border-radius:20px`、`backdrop-filter:blur(25px)`；菜单项 `border-radius:8px`、hover `#00000005`、高 2.57em。

**Marvis 输入区**：`.semi-aiChatInput` —— `padding:20px`、`border-radius:12px`；**两态**：默认 `pointer-events:none` 单行收起态（footer `margin-top:-32px` 叠在输入框上），`.is-open` 才展开（`padding:20px`、footer `margin-top:12px`、编辑器 `white-space:pre-wrap`）。

### Oryx 现状（已逐行核实）

| 维度 | Oryx 现状 | Marvis | 差距 |
|---|---|---|---|
| 内容列宽 | `.wrap { max-width:880px }` 固定 | `min(1004px, 100%-88px)` 自适应 | 窗口变宽时 Oryx 浪费两侧空间 |
| 响应式 | `fitTopbar()` 量 `#center` 宽度，手动 4 档隐藏元素 | ResizeObserver → CSS 变量 + 容器查询 | Oryx 是「藏元素」，Marvis 是「连续缩放」 |
| 头像 | `.msg .av` 30×30 | 24×24 | Oryx 偏大 |
| 用户气泡 | `padding:9px 14px`、radius `12/12/4/12`、max-width 78% | `padding:20px`、radius 20px、max-width 600px | Oryx 偏扁偏小 |
| 消息操作栏 | **完全没有** | hover 显示复制/重试 | 缺功能 |
| 输入框 | `height:54px` 硬编码，无自适应 | 收起↔展开 + 多行 | 输长文本要内部滚动 |
| 思考面板 | header `padding:8px 11px`、标题非 600 | header `padding:16px`、标题 600 | 规格偏小 |
| 侧栏 | 实体栏 `clamp(168px,236px,24vw)`、有边框 | 悬浮 88px↔196px、毛玻璃圆角 20px | 形态差异大 |

### 目标

在**不推翻现有基底架构**的前提下（前序约束：前端单文件 vanilla JS、不引框架不引构建步骤），把对话区向 Marvis 靠拢：

1. **列宽自适应** —— 内容列与输入框共用一条宽度公式，窗口变宽时一起变宽（Marvis 的核心机制）
2. **消息操作栏** —— 补齐 Marvis 有而 Oryx 完全没有的复制 / 重试
3. **输入框多行自适应** —— 高度随内容增长
4. **规格对齐** —— 头像、气泡、思考面板的尺寸/间距对齐 Marvis 实测值

侧栏毛玻璃悬浮形态**不在本轮范围** —— 那是整体形态改动，与"对话界面布局"是两块，且 Oryx 侧栏已有拖拽 + 折叠 + localStorage 持久化，替换成本高收益低。

## 实施方案

全部改动集中在 `core/web/index.html`（单文件），后端仅新增 1 个重试接口。

### 1. 列宽自适应（对齐 Marvis 的宽度机制）

**做法**：用 CSS 变量统一驱动内容列与输入框宽度，取代两处独立的 `max-width:880px`。

CSS：
```css
#center {
  /* 内容列与输入框共用的宽度：随主区宽度变化，上限 1004px */
  --chat-col: min(1004px, calc(100% - 88px));
}
.wrap { max-width: var(--chat-col); margin: 0 auto; }
.cbox { max-width: var(--chat-col); margin: 0 auto; }
.modehint { max-width: var(--chat-col); margin: 0 auto 7px; }
```
`#attbar` 当前没有 max-width（满宽、与 `.cbox` 不对齐），一并补上 `max-width:var(--chat-col); margin:0 auto`。

> `#center` 是 flex 子项，`100%` 解析为其内容盒宽度 —— 正确。

**JS 侧**：现有 `fitTopbar()` 已经在量 `#center` 宽度做 4 档自适应，**保留它**（Marvis 也是 JS 量 + CSS 变量，只是 Marvis 用连续插值，Oryx 用离散档位 —— 离散档位对 Oryx 的元素数量更合适，不必照搬插值）。

### 2. 消息操作栏（复制 / 重试）

**DOM**：`addMsg()` 生成的 `.msg` 里，在 `.body` 之后追加一个 `.mactions` 容器。

```html
<div class="msg bot">
  <div class="av">OX</div>
  <div class="body">…</div>
  <div class="mactions">
    <button class="maction" data-act="copy" title="复制">…</button>
    <button class="maction" data-act="retry" title="重新生成">…</button>
  </div>
</div>
```

**CSS**（对齐 Marvis 的 `.semi-ai-chat-dialogue-action`）：
```css
.mactions { margin-top:8px; visibility:hidden; display:flex; gap:2px; }
.msg:hover .mactions, .mactions:focus-within { visibility:visible; }
.maction { width:24px; height:24px; border:0; background:transparent; color:var(--muted);
           border-radius:var(--r); display:grid; place-items:center; cursor:pointer; }
.maction:hover { background:var(--panel-2); color:var(--ink); }
```
位置：`.mactions` 作为 `.msg` 的第三个 flex 子元素 → 落在头像列下方（`.msg` 是 `display:flex`，头像 30 + gap 12 = 42px 缩进，正好对齐正文列左缘）。助手消息才显示，**用户消息不显示**（Marvis 只在 assistant 侧有 action）。

**复制**：复用现有 `toast()`（L2279）与 `navigator.clipboard.writeText` 模式（参考 L4915 的 `#docCopy` 实现）。

**重试**：需要后端支持，见下。

### 3. 后端：重试接口（新增，1 个）

Marvis 的「重新生成」= 删掉该轮助手回复，用同一提问重跑。

Oryx 的 `store.trim_messages(task_id, keep)`（[store.py](file:///d:/项目/Oryx/core/oryx/store.py#L932)）已经存在 —— 按 rowid 保留前 N 条。核心逻辑可直接复用。

新增 `POST /api/chat/retry`：
- 入参：`task_id`（会话 id）
- 行为：读该 task 的消息，找到**最后一条 user 消息**，trim 掉它之后的所有消息，然后以该 user 消息内容为 goal 重新 `chat.run`（带 `session_id=task_id`，复用同一 task）
- 返回：`{"ok": true, "task_id": ...}`

实现要点：
- 用 `store.messages_for_task(task_id)`（[store.py](file:///d:/项目/Oryx/core/oryx/store.py#L545)）找最后一条 user 消息
- trim 时 `keep` = 该 user 消息在 messages 列表里的下标 + 1，**保留**这条 user 消息（Marvis 保留用户提问，只重生成回答）
- 走 `agent.call_async("chat.run", goal=..., session_id=task_id)`，与现有 [server.py](file:///d:/项目/Oryx/core/oryx/server.py#L366) 的 `/api/chat` 同路径

**前端调用**：`retry` 按钮 → `POST /api/chat/retry { task_id: S.current }` → 清空该条助手消息的 DOM 与后续消息 → 事件流自然重放新回复。

### 4. 输入框多行自适应

**CSS**：去掉 `height:54px` 硬编码，改 `min-height` + `max-height` + 滚动。
```css
#input { min-height:54px; max-height:200px; overflow-y:auto; }
```

**JS**：`autoGrow()` —— 输入时按 `scrollHeight` 调整 `style.height`，发送后复位到 54px。
```js
function autoGrow() {
  const el = $('#input');
  el.style.height = 'auto';
  el.style.height = Math.min(el.scrollHeight, 200) + 'px';
}
```
绑定到 `#input` 的 `input` 事件；`send()` 里发送后调用 `autoGrow()` 复位。

> 注意 `send()` 开头已有 `input.value = ''`（L2992），复位要在那之后调。

### 5. 规格对齐（Marvis 实测值）

| 选择器 | 改动 | 依据 |
|---|---|---|
| `.msg .av` | 30×30 → **24×24**；字号 11 → 10 | Marvis `.semi-ai-chat-dialogue-avatar` 24×24 |
| `.msg .bubble` | font-size 14 → **15px**、line-height 1.72 → **1.7** | Marvis chat-text 16px/26px，Oryx 整体更紧凑，取 15px 折中 |
| `.msg.user .bubble` | `padding:9px 14px` → **`12px 16px`**；radius `12/12/4/12` → **`16px 16px 4px 16px`**；max-width 78% → **`min(600px, 78%)`** | Marvis userBubble padding 20px / radius 20px / max-width 600px |
| `.reason` | radius `var(--r)` → **`var(--r-lg)`** | Marvis reasoning-wrapper radius 12px |
| `.reason-head` | padding `8px 11px` → **`12px 14px`**；title 加 `font-weight:600` | Marvis header padding 16px / title 600 |
| `.reason-body` | padding `0 12px 11px` → **`12px 14px`** | Marvis content padding 12px 16px |

### 6. 顺带修掉两处已确认的小问题

调研中发现的两个既存缺陷（都在本轮改动范围内，一并修）：

1. **`.crow .tbtn` 被 `.chipsbar .tbtn` 覆盖**（[index.html](file:///d:/项目/Oryx/core/web/index.html#L564) vs L1988，同特异度后者靠后）—— 前者定义的实心胶囊样式实际不生效。删掉被覆盖的 `.crow .tbtn` 规则块。
2. **`#attbar` / `#modeHint` 与 `.cbox` 不对齐** —— 补 `max-width:var(--chat-col); margin:0 auto`（见第 1 条）。

> 调研还发现 `.narr` / `.thinking` 两条 CSS 规则是死代码（无元素使用），`body.narrow` class 无对应 CSS 规则。这些不在本次范围，**不动**，避免无关改动。

## 风险与边界

- **重试接口是本轮唯一的后端改动**，会写库（trim 消息）。trim 逻辑复用已验证的 `store.trim_messages`，且保留 user 提问 —— 不会丢用户输入。
- **消息操作栏只加在助手消息上**，用户消息不加（与 Marvis 一致）。
- 侧栏形态**不改** —— 见 Context 的说明。
- 不引任何框架/构建步骤，保持单文件 vanilla JS（项目硬约束）。
