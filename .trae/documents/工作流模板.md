# 第五批 · 工作流模板（可复用编排存档）

## Context

第四批把工作流编排引擎落地了（`core/oryx/workflow.py` + 工具 + RPC + 路由 + 存储），第五批（前端接入）把界面补齐了。现在整条链路是通的，但有一个结构性缺口：

**只有模型能发起编排，用户手写不了。** `workflow_run` 工具的 plan 由主模型现场生成，用户既看不到既有的编排长什么样，也没法把一份跑通的编排存下来复用 —— 每次都得重新让模型"临场发挥"一份几乎一样的 plan。

上一批的文档里明确写了「不做保存工作流为命令 —— 需要脚本持久化 + 命令注册」，那是当时的取舍。现在要补上，但**只补最关键的那一半**。

### 本批目标

让用户能：
1. 把一份编排定义**存成模板**（手写 JSON，或从已跑完的 run 反向存）
2. 从工作流页**一键触发**模板
3. 模板跑起来仍走现有 `workflow_run` 链路 —— 权限、审计、子 Agent 白名单校验全部不绕过

### 硬约束

- 不推翻现有基底架构，只做增量。模板是"另一条入口"，不是新链路
- 前端单文件 vanilla JS，不引框架、不引构建步骤
- 模板与"运行记录"在数据层与 UI 层都要分得清

### 本批不做

- **可视化编排编辑器**（阶段/step 的表单化编排）：代价最大，且与"编排由模型决定"的既有立场冲突。等模板数量真的多了再做
- **斜杠命令**：现在连命令注册表都没有，做出来是一整套子系统（注册表/解析/补全/帮助/作用域），不是"加一个功能"；`/run <模板名>` 在工作流页有个按钮之后价值接近零。插件的 `commands/` 目录至今未消费（`plugins/README.md:44`），要接就得先决定插件命令的语义，是需要用户拍板的设计题，留到下一个批次

## 关键事实（已确认）

- `WorkflowPlan.parse(raw)` 是唯一的定义校验入口：goal 必填、stages 非空、step 必须有 agent 与 goal、needs 引用的 step 必须存在。错误信息本来就是中文，可直接透给用户
- `WorkflowRun._persist_start()` 只存了 name/goal/status/args —— **plan 本身没落库**，所以"从 run 存成模板"必须先补存 plan
- `WorkflowPlan` **没有 `to_dict()`** —— 存 plan 前必须补，且字段名要与 `parse()` 的入参严格同构（自己存自己读不回来是最容易犯的错）
- `loop.run_workflow()` 里已经做了子 Agent 白名单检查（`known = set(self.agents.agents)`）—— 模板触发复用它，白名单天然不被绕过
- 建表全用 `CREATE TABLE IF NOT EXISTS`，**没有 schema 版本号、没有迁移脚本**；加列的 ALTER 套路全仓只有一处（`core/oryx/indexer.py:289-295`）。所以新功能一律**新建表**，不给旧表加列
- `app_dir()` 优先读 `ORYX_HOME`，否则 Windows 走 `%APPDATA%/Oryx` —— 库路径跟着它走
- IPC 每个请求是独立线程（`core/oryx/ipc.py:186`），内核 `self._workflow` 只有**一个槽位**：并发跑两个 run 会互相覆盖，取消功能就指错对象了。所以模板触发**保持阻塞语义**，不加"立即返回 run_id 后台跑"
- `/api/workflows` 的路径参数路由 `/{run_id}` 会吃掉同名单段路径 —— `/templates` 必须注册在它前面
- 前端工作流页的代码区块在 `/* ══════════ 工作流编排` 与 `S.appFilter = '';` 之间，`tests/check_web_script.py` 只对这一段做括号/div 配平检查

## 实施

### 1. `core/oryx/store.py` — 两张新表 + 存取方法

`CONVERSATION_SCHEMA` 末尾加：

```sql
-- 工作流模板：用户手写的编排存档。与 workflow_runs 是两回事（模板=可复用存档，run=执行记录）
CREATE TABLE IF NOT EXISTS workflow_templates (
    id          TEXT PRIMARY KEY,
    name        TEXT NOT NULL,
    description TEXT,
    plan        TEXT NOT NULL,
    args        TEXT,
    created_at  REAL NOT NULL,
    updated_at  REAL NOT NULL,
    run_count   INTEGER DEFAULT 0,
    last_run_at REAL
);

-- run 的 plan 本体（供"把这次运行存成模板"）。
-- 单独建表而不是给 workflow_runs 加列：加列要走 ALTER 迁移，
-- 新表只要 CREATE TABLE IF NOT EXISTS，旧库零迁移成本。
CREATE TABLE IF NOT EXISTS workflow_run_plans (
    run_id     TEXT PRIMARY KEY,
    plan       TEXT NOT NULL,
    created_at REAL NOT NULL
);
```

新增方法（upsert 抄 [save_automation](file:///d:/项目/Oryx/core/oryx/store.py#L600) 的 `ON CONFLICT` 写法）：

- `save_workflow_template(item)` — upsert
- `list_workflow_templates()` — 列表**不含 plan 正文**，只带 `stage_count` / `step_count`（解析 JSON 算出来）
- `get_workflow_template(tid)` — 含 plan
- `delete_workflow_template(tid)`
- `save_workflow_run_plan(run_id, plan)` / `get_workflow_run_plan(run_id)`
- `mark_workflow_template_run(tid)` — 记一次触发（`run_count` / `last_run_at`）

### 2. `core/oryx/workflow.py` — `WorkflowPlan.to_dict()`

补 `to_dict()`：stages → steps 的字段名必须与 `WorkflowPlan.parse` 的入参**完全对称**（`name`/`goal`/`stages[].name`/`stages[].steps[].{id,name,agent,goal,needs,parallel}`）。同时给 `WorkflowRun._persist_start()` 加一次 `store.save_workflow_run_plan(self.id, self.plan.to_dict())`。

### 3. `core/oryx/loop.py` — 模板触发入口

`AgentRuntime` 加 `run_workflow_template(tid, args)`：取模板 → 取出 plan → **复用现有的 `self.run_workflow(plan, args)`** → 成功后 `store.mark_workflow_template_run(tid)`。

不新开任何执行路径：白名单校验、审计、权限全在 `run_workflow` 里。

### 4. `core/oryx/agentd.py` — RPC

`self.methods` 里加：

- `workflow.template.list` → `{"templates": [...]}`
- `workflow.template.get` → 模板详情
- `workflow.template.save` → 校验 + 存盘（校验失败抛 `ValueError`，HTTP 层据此回 400 —— 与 `workflow_run` 同一约定）
- `workflow.template.delete`
- `workflow.template.run` → 触发，返回体与 `workflow.run` **完全同形**（把 `workflow_run` 那段包装抽成共用小函数）
- `workflow.plan` → 取某次 run 的 plan（供"存成模板"）

### 5. `core/oryx/domains/workflow.py` — 路由

**必须注册在 `@router.get("/{run_id}")` 之前**：

- `GET /api/workflows/templates` — 列表
- `POST /api/workflows/templates` — 新建/更新
- `GET /api/workflows/templates/{tid}` — 详情
- `PUT /api/workflows/templates/{tid}` — 更新
- `DELETE /api/workflows/templates/{tid}` — 删除
- `POST /api/workflows/templates/{tid}/run` — 触发（阻塞，`asyncio.to_thread` 包住）
- `GET /api/workflows/{run_id}/plan` — 取 run 的 plan

沿用 `_map()` 的 400/404 语义。

### 6. `core/web/index.html` — 模板 UI

- `S.wf` 加 `tab: 'runs'` 与 `templates: []`
- 工作流页加**页内分段 tab**（复用 `.subtabs`），切「运行记录 / 模板」。运行中卡片**始终置顶** —— 跑的时候切到模板 tab 也要能看到进度
- 模板卡用 `.grid` + `.skillcard`（技能广场同款，有 `.sact` 操作行；`.tpl` 是"点一下填表单"语义，不适合有操作按钮的卡片）。卡内：名称、`.badge` 显示「3 阶段 / 7 步」、`.hint` 显示上次运行时间，操作按钮 = 运行 / 编辑 / 删除
- 起步模板：`.tpl` 静态卡（同 `AUTO_TEMPLATES`），点击预填编辑器
- 编辑器：`openModal({wide:true})`，plan 用 `<textarea class="inp">`。**校验错误显示在弹层内的 `.hint` 里**，不用 toast —— toast 会自动消失，用户看不到错误细节
- "存成模板"入口：在 `openWorkflowDetail` 弹层加按钮 → 取 `GET /api/workflows/{run_id}/plan` → 预填同一个编辑器
- 触发：卡片「运行」按钮 → `POST /api/workflows/templates/{tid}/run` → 按钮进 pending 态（几分钟内禁用）→ SSE 负责后续进度。**不改 `S.busy`**（那是对话页的）
- textarea 里的 JSON 同样要过 `esc()`

### 7. `core/tests/verify_batch4_g1.py`（新建）

照 `verify_batch4_f1.py` 的隔离 `ORYX_HOME` 模式（破坏性接口只打隔离库）。用例：

1. 建模板 → 列表能查到 → 详情含 plan
2. **无效 plan 保存被拒**（缺 goal / 空 stages / 未知 agent）
3. **按模板触发时白名单没被绕过**：模板里写一个不存在的 agent id，断言返回"没有这个子 Agent"
4. `plan` 往返：`WorkflowPlan.to_dict()` → `WorkflowPlan.parse()` 能解析回来（这是最容易犯的错）
5. run 之后 `workflow_run_plans` 里确实落了那份 plan，`GET /{run_id}/plan` 取得到
6. 删除 → 404
7. 隔离断言：临时库不含用例名数据
