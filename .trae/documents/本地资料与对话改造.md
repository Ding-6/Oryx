# 第六批 · 本地资料四视图与对话界面改造

## Context

用户对照 Marvis 提出四条具体不满：

1. 「此电脑不要只是选择工作区，而是和 marvis 一样的可以点击查看文件夹里的内容」
2. 「应用库也是，要是可以打开的应用，目前可以只把桌面上的添加上去，然后后续在应用库里添加一个我可以自己添加的功能」
3. 「图片库要和 marvis 一样是我的图片而不是图标」
4. 「知识库……现在的不美观，也不好看，也不好用」＋「现在的对话界面也是都在右边，不好看……分工要明确」

我做了 Marvis 的逆向分析（`D:\Program Files\Tencent\Marvis\Application\1.60.3000.228\marvis-offline-page\assets\treemap-KZPCXAKY-DqrP9bPu.js`，8.2MB Vite 产物），并用浏览器实测了 Oryx 现状。**实测结果修正了两条用户判断**：

- **图片库已经是真图**：600 张全部是真实缩略图（`/api/image/thumb` 走 Pillow），零个 fallback。真正的问题不是"图标 vs 图片"，而是①分类 tab 是**假的** —— `imgCat()` 靠文件名关键词猜，"人物印象/足迹地点/时光长廊"这四个分类在 Windows 上根本匹配不到东西（实测只有"全部图片/照片/图表插画/其他"四类有内容）；②排列是网格，Marvis 是胶片条 + 尺寸滑块 + 年月选择器。
- **对话不是"都在右边"**：CSS 明确写着左对齐（`index.html` L383-386）。"都在右边"的观感来自两个真实原因 —— ①`.wrap{max-width:760px;margin:0 auto}` 整列居中，而右侧栏 380px 常驻，视觉重心偏右；②用户气泡虽然收缩到内容宽度，但**紧贴左侧头像**，右边完全没有锚点。Marvis 是**用户右对齐带气泡、机器人左对齐无气泡**。

Marvis 的此电脑是三栏列式浏览（`columnPaths` + `dirCache` + 文件系统监听增量更新），每个文件项字段 `{path,name,extension,isDirectory,isHidden,size,lastModified}`。

### 目标

把四个本地资料视图与对话界面对齐 Marvis 的形态与手感，**只做增量、不推翻基底架构**。

## 硬约束

- 前端单文件 vanilla JS（`core/web/index.html`，约 250KB，内联 CSS/JS，无构建步骤），不引框架
- 复用既有件：`.navitem[data-view]` / `S.localView` / `pageShell()` / `openModal()` / `api()` / `esc()` / `.grid` / `.skillcard` / `.subtabs` / `.searchfield` / `.card` / `.badge` / `.kbd` / `.hint` / `.empty`
- **不新增 CSS 变量**，深色主题自动跟随
- 工具权限严格遵循 L0/L1/L2 分级；目录浏览与启动应用不得绕过安全基线
- 桌面端 `apps/desktop/src-tauri/target/release/core/` 必须同步

## 实施

### 1. 此电脑 → 目录浏览器（新增）

**后端**：新增 `core/oryx/localfs.py`

- `safe_browse(path) -> Path`：安全护栏。**不能复用 `_under_allowed_roots()`** —— 它按 `allowed_roots` 判，而「此电脑」要浏览整盘。护栏要求：路径 resolve 后必须存在、必须是目录、必须在盘符根之下（挡 `\\?\`、`\\.\`、UNC、`..` 越界）、**不得落在 `config.forbidden_paths`**（`C:\Windows`、`Program Files`…）、符号链接/junction resolve 后再判一次
- `list_dir(path, show_hidden=False, limit=500, offset=0)`：单层 `os.scandir`（**不递归**），条目字段 `{name, path, is_dir, size, mtime, ext, hidden}`，单次扫描上限 20000 项、返回上限 500 + `offset` 游标 + `truncated` 标记

**HTTP**（`server.py`，放在现有 `/api/drives` 旁）：
- `GET /api/fs/list?path=...&show_hidden=0&limit=500&offset=0`
- 路径走 **query** 而非 path param（Windows `C:\` 转义坑）
- 用**同步 `def` 端点**（FastAPI 线程池），别复制 `/api/drives` 那个 async+阻塞调用的隐患

**权限语义**：目录树可浏览，但**文件内容读取仍受 `allowed_roots` 约束**（`image_thumb` 已是如此）。「可看目录树，不可越权读内容」——与 Marvis 一致且不破坏安全基线。

**前端** `renderPC()` 改三栏：**左轨磁盘列表（复用现有 `.dlist`）+ 中栏目录内容（面包屑 + 条目列表）+ 右栏预览**。

不做 Marvis 的 Miller 列式（要维护 `columnPaths`+`dirCache`、一屏 N 个并发请求、窄窗口挤爆、深路径横向滚动）；逐级钻取 + 面包屑只需单请求、状态简单、「设为工作区」落点天然。保留 `dirCache` 结构留白，列式可后续增量加。

「设为工作区」保留：现 `POST /api/workspace` 不动，工具栏加按钮。

### 2. 应用库 → 真图标 + 可启动 + 用户自定义

**图标提取**（新增 `core/oryx/appicon.py`，不引新依赖）：
- `.lnk` 目标解析：`WScript.Shell.CreateShortcut(path).TargetPath`（PowerShell，**批量一次调用** + 按 mtime 缓存），复用 `core/oryx/syssettings.py` 的 `_run_ps` 模式
- 取图标：`ExtractIconExW` → HICON → `GetIconInfo` + `GetDIBits` 取 BGRA → Pillow 存 PNG（**必须 `DestroyIcon`，否则 GDI 句柄泄漏**）；失败回退 `SHGetFileInfoW(SHGFI_ICON)`，再失败回退现有首字母色块
- 端点 `GET /api/app/icon?id=...` 走线程池 + 磁盘缓存（key = 目标路径 + mtime）+ `Cache-Control: private, max-age=86400`

**桌面应用优先**：`manage.list_installed_apps()` 增加 `%USERPROFILE%\Desktop`、`C:\Users\Public\Desktop` 的 `.lnk`（`source="desktop"`），与卸载注册表、开始菜单合并。

**启动应用**：`POST /api/apps/launch {id}` —— **只接受 id，不接受任意路径**（否则该端点退化成"运行任意程序"的通用原语）。服务端查表解析目标 → 校验存在 → `os.startfile(target)`。这是**用户手势**（等价双击桌面图标），不进 Agent 工具白名单，故不占 L 级。给模型开 `open_app` 工具需 L2 门禁，**本批不做**。

**用户自定义**：存 `app_dir()/apps.json`（即 `%APPDATA%\Oryx\apps.json`），不建 SQLite 表 —— 零 schema 迁移、人类可读可手改（`features.yaml` 有先例）。字段 `{id,name,target,note,created_at}`，`target` 支持 exe/lnk/目录。端点 `GET/POST/PUT/DELETE /api/apps/custom`。前端应用库头部加「＋ 添加应用」，弹层可编辑名称/路径/删除，路径用 Tauri `dialog.open` 选（复用 `pickFiles()` 的 `HAS_TAURI` 分支）。

### 3. 图片库 → 删掉假分类，改 Marvis 式浏览

- **删掉 `IMG_CATS` 里匹配不到东西的假分类**（人物印象/足迹地点/时光长廊/图片识字）—— 假的分类比没有分类更糟
- 换成诚实的筛选：全部 / 最近添加 / 截图（按目录名精确匹配 `Screenshots`、截图、Screen Shot）/ 大文件（按像素尺寸）
- 排列改 Marvis 式**胶片条**（复用现有 `.filmstrip` CSS），加**尺寸滑块**（Marvis 有）
- 缩略图本身不动（已经是真图）

### 4. 知识库 → Marvis 式卡片集合

**不改成"用户自建知识库实体"**（那是新领域模型，要独立索引与生命周期，代价过大）。改为把现有索引**按目录分组成 Marvis 形态的卡片集合** —— 语义仍是"我索引了哪些内容"，视觉是 Marvis 的"库名 + N 个文件 + 更新时间 + 可勾选文件列表"。

- 后端：`indexer.library_groups()` 按文件所在目录分组（文件数 + 最近 mtime），经 `agentd.py` 新 RPC `index.libraries` / `index.library` 暴露
- 前端 `renderKnowledge()` 重排：
  - 横幅**按钮右对齐**（现在 `.bact` 换行落到标题下方 —— 给 `.bmain` 加 `flex:1;min-width:0`）
  - 顶部三段检索（混合/全文/语义）保留
  - 卡片网格：每卡 = 名称 + 文件数 + 更新时间 + 展开文件列表
  - 统计方块收进卡片区
  - 「项目文档」独立成一张卡（现在是无边框 `<code>` 平铺 Markdown 原文，无高亮 —— 改成摘要 + 在对话里维护）

「订阅库/精选库」继续 disabled（无内容源）。

### 5. 对话界面 → 用户右对齐 + 模式真正生效

**CSS**（`index.html` L355 / L383-386）：
```css
.wrap { max-width:880px; }                     /* 与 .cbox 同步加宽 */
.msg.user { flex-direction:row-reverse; }       /* 头像在右 */
.msg.user .body { align-items:flex-end; }
.msg.user .bubble { max-width:78%; border-radius:var(--r-lg) var(--r-lg) 4px var(--r-lg); }
```
机器人侧保持左对齐无气泡（`background:transparent`），与 Marvis 一致。

**顺带修 bug**：`index.html` L2857 `S.assistant.parentElement.parentElement.insertBefore(agentLine(...), S.assistant.parentElement)` 把 Agent 状态行塞进了 flex 行里（头像与正文之间）。改为 `S.assistant.parentElement.prepend(agentLine(...))`，让它进 `.body` 列、位于气泡上方。

**模式真正生效（"分工要明确"）**：顶栏 `#interSeg`（L1892）**已经是**问答/规划/执行三段，与 Marvis 完全对齐。问题不在缺 UI，而在：
- `send()`（L2782）`POST /api/chat` **没传 `interaction`** —— 靠 config 落盘，换模式后立刻发送有竞态。`ChatRequest.interaction` → `chat.run` → `rt.run(interaction=)` 全链路已通，**零后端改动**
- `S.policy`（只读/受控/完整）**只拼了提示词、没真正降权**（L2770-2772）。改为：`send()` 传 `interaction: S.policy ? POLICY_MODE[S.policy] : S.interaction`（`POLICY_MODE` L3065 已有映射）

另外在输入框上方显示当前模式一行（如"当前：规划模式 · 只读调研"）。

## 高风险点

1. **目录浏览的路径穿越与 Windows junction 逃逸** —— 必须 resolve 后再判 forbidden + 盘根边界，不能只做字符串前缀判断
2. **launch 端点若接受任意路径 = 通用执行原语** —— 必须 id 白名单
3. **GDI 句柄泄漏** —— `ExtractIconEx` 后不 `DestroyIcon` 会耗尽桌面堆
4. **图标提取的兼容性** —— 非 Windows / 无 Pillow / 无 PowerShell 环境要能优雅回退到首字母色块
5. `os.startfile` 目标不存在时的异常

## 本批不做

- Miller 列式多级浏览（保留 `dirCache` 结构留白，后续增量）
- 图片的真实语义标签（人物/地点/长廊）—— 需要向量化管线
- 「订阅库/精选库」内容源与许可
- 用户自建独立索引的知识库实体（多库生命周期）
- `open_app` 作为 Agent 工具（需 L2 策略门禁，另批）
- UWP 应用（`shell:appsfolder`）与图标
- 文件系统实时监听（先做手动刷新）
- 前端框架 / 构建步骤（保持单文件 vanilla）
